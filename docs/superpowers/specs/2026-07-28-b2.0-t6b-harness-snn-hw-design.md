# Fase B2.0 · T6b — Harness_SNN (HW): caratterizzazione full-system di `Donatello_Tier@BALANCED`

> **Design doc (brainstorming 2026-07-28).** Segue T6a (validazione RTL, chiusa). Prossimo passo dopo approvazione:
> `writing-plans`. Base: `FaseB2.0/README.md` (bitstream per harness), spec T6 §6, flusso Fase B (`matlab/axi/`).

**Goal.** Caratterizzare in **hardware** lo stesso `Donatello_Tier@BALANCED` validato bit-exact da T6a: **utilizzo
risorse reale post-place&route** (LUT/FF/DSP/**BRAM**), **potenza realizzata** (SAIF), e un **bitstream** flashabile
per PYNQ-Z1 — tutto sul **sistema completo** (Tier + wrapper AXI4-Lite + Zynq PS7), col clock all'**Fmax del sistema**.

**Architettura (una riga).** Il VHDL del Tier (generato in T6a) è avvolto in un **wrapper AXI4-Lite** adattato al suo
I/O fisico + edge-trigger; un **block design** Zynq (board preset PYNQ-Z1) lo integra col PS7; Vivado sintetizza,
place&route, misura utilizzo/timing/potenza e scrive il bitstream; una **cosim AXI** verifica che i param letti dal
PS == blocco. Replica il flusso Fase B (`matlab/axi/`) applicato al Tier. **Core SNN congelato; VHDL mai a mano.**

**Tech Stack.** Vivado 2026.1 (`create_bd`, block design PS7, `synth`/`impl`/`write_bitstream`, `report_utilization`/
`report_timing`/`report_power`, SAIF) · Verilog per il wrapper AXI (mixed-language sul DUT VHDL) · work-dir corta `D:/zbd_*`.

## 1. Scope

**In scope (T6b), tutto full-system:**
- **6a** utilizzo post-route reale (LUT/FF/DSP/**BRAM**) + timing del sistema Tier+AXI+PS7.
- **6b** potenza SAIF (typical + worst) con gate di confidenza.

**Fuori scope:** costanti `e_AC`/`e_MAC` da micro-datapath e baseline **ANN densa** — già misurate in Fase B,
indipendenti dal blocco. La validazione RTL (bit-exact) è **T6a** (fatta).

**Livello (decisione utente):** **full-system**, non OOC. I numeri di utilizzo/potenza includono l'overhead di AXI
SmartConnect (il PS7 è hard-IP, non consuma PL) → rappresentano il **sistema deployato reale**, non il blocco isolato.

## 2. Wrapper AXI4-Lite (il prerequisito di tutto T6b)

Adatta `matlab/axi/snn_b2_axi_lite.v` (protocollo AXI dal template Vivado: write/read FSM, registri `slv_reg`)
all'interfaccia del Tier. **Differenze dal wrapper B2** (che aveva `xn` 19b + `start`/`done` espliciti):

| | wrapper B2 (`snn_top_b2`) | wrapper Tier (T6b) |
|---|---|---|
| ingressi | `xn` normalizzati, 19b | **`s,v,dv,v_l` FISICI, 32b** (`sfix32_En20`) |
| trigger | `start` esplicito del DUT | **edge-trigger interno** del Tier (niente `start`) |
| done | porta `done` del DUT | **`ce_out`** del Tier (valid, pulsa a fine inferenza) |

**Mappa registri** (offset AXI):
- `W 0x00–0x0C` = `s,v,dv,v_l` (32b interi con segno, `Q?.20`).
- `W 0x10` bit0 = **commit/start** (pulse sul fronte).
- `R 0x10` bit0 = **status/done**.
- `R 0x14–0x24` = `v0,T,s0,a,b` (21b `Q7.13`, sign-ext a 32b).

**Trigger sincrono (il punto delicato).** Il Tier è edge-triggered: se il PS scrive i 4 ingressi uno alla volta e
il wrapper li instrada *continuamente* al Tier, il primo cambio farebbe partire un'inferenza su ingressi **parziali**.
→ Il wrapper tiene i 4 registri come **buffer**; un secondo set *committed* (`s_c,v_c,dv_c,v_l_c`) si aggiorna dai
buffer **solo su start-pulse**, e il Tier riceve i `_c`. Così i 4 ingressi cambiano **sincroni** (1 edge) → **1
inferenza per commit** (coerente col finding "ingressi sincroni", `HDL_PHASE §9`).

**Done via `ce_out`.** Il wrapper latcha `params` + `done` quando `ce_out` pulsa: `if(start) done<=0;
if(ce_out) begin params_lat<=...; done<=1; end` (come il B2 con `done_w`). ⚠️ **Da verificare in impl** che `ce_out`
sia l'unico impulso valido per control-step; fallback: contatore di latenza (`done` dopo ~364+ clk dal commit).

**Nota istanziazione:** le porte del Tier sono **già scalari** (`std_logic_vector` 32b/21b), quindi il wrapper Verilog
istanzia `Donatello_Tier` (VHDL) **direttamente** (mixed-language, come i TB T6a) — **niente flat wrapper** (a
differenza del B2 che appiattiva `xn` composite).

**Limite noto (irrilevante qui):** su due commit con ingressi **bit-identici** l'edge non scatta (§3.1.4) → nessuna
nuova inferenza. Con traiettorie reali `Q?.20` non accade; la cosim usa ingressi reali del dataset.

## 3. Block design + clock

**Block design** (Tcl, pattern `matlab/axi/build/bitstream_board.tcl`): Zynq **PS7 con board preset PYNQ-Z1**
(`www.digilentinc.com:pynq-z1:part0:1.0` — DDR/MIO/clock reali) + il wrapper AXI (packaged IP) + **AXI SmartConnect**.
Base slave su `M_AXI_GP0`.

**Clock = Fmax del full-system (decisione utente).** Determinato via synth/impl **io-timed**: target iniziale
(≈ Fmax OOC del Tier@BAL dal trade-off study, ~58 MHz), synth+impl, `report_timing_summary` → WNS; **stringi finché
WNS→0⁺** (o allarga se negativo). Riuso del metodo/`impl_point.tcl` del trade-off (`matlab/study_tradeoff/common/`),
adattato al block design. Il **bitstream** usa il FCLK all'Fmax così trovato. ⚠️ **Non comparabile** con gli 8 MHz
Fase B (dichiarato nel report).

## 4. 6a — Utilizzo post-route + timing

Synth + impl del block design → `report_utilization -hierarchical` + `-file` (LUT/FF/DSP/**BRAM** — il full-impl
cattura la BRAM, colmando il "BRAM non catturata" degli OOC) + `report_timing_summary` (WNS all'Fmax). Attribuzione:
il report gerarchico separa Tier vs AXI/SmartConnect.

## 5. 6b — Potenza SAIF

Stimolo tipico + worst dal dataset (pattern `gen_stimulus.m`/`gen_saif_b2.sh`): il PS-side pilota il wrapper (o un
TB AXI-master) con sequenze reali → `launch_simulation post-implementation -type timing` con `open_saif/log_saif/
read_saif` → `report_power`. **Gate: Confidence ≥ Medium** (se Low → il SAIF non copre, si investiga). Collector
`collect_results.py` → `results.csv`.

## 6. 6c — Bitstream + cosim AXI

`write_bitstream` → `snn_tier_donatello.{bit,hwh,xsa}` (board preset, ROOT corto `D:/zbd_*`). **Cosim AXI** (pattern
`matlab/axi/axi_tb.v`): un master AXI scrive `s,v,dv,v_l` → commit → poll done → legge `v0..b` → confronta col
**blocco** (`tier_block_params`, l'oracolo T6a) su ≥3 control-step → **bit-exact** (cancello).

## 7. Cancelli (assert + provati sensibili)

| Cancello | Cosa prova | Sensibilità |
|---|---|---|
| **AXI-COSIM** | params letti dal PS (via AXI) == blocco, ≥3 control-step | 1 LSB su un param atteso → mismatch |
| **SYNC** | i 4 ingressi arrivano al Tier **sincroni** (1 inferenza per commit) | commit con ingressi sfalsati → doppia inferenza rilevata |
| **POWER-CONF** | `report_power` Confidence ≥ Medium | SAIF vuoto/parziale → Low → blocca |
| **TIMING** | WNS ≥ 0 all'Fmax scelto (il bitstream chiude) | clock troppo veloce → WNS<0 → allarga |

## 9. Gotcha / vincoli

1. **`ce_out` come done**: verificare in impl che sia l'impulso valido per control-step; fallback contatore latenza.
2. **Trigger sincrono**: buffer + commit (i 4 `_c` cambiano insieme) — altrimenti inferenza su ingressi parziali.
3. **Work-dir SENZA spazi** (`D:/zbd_tier_hw`); board files in `C:/AMDDesignTools/Boards_Drivers`; path 260.
4. **Wrapper in Verilog** su DUT VHDL (mixed-language, come i TB T6a); niente flat wrapper (porte Tier già scalari).
5. **Fmax non comparabile con Fase B** (8 MHz): dichiararlo nel report.
6. **Convenzioni**: commit conventional senza `Co-Authored-By`; stage esplicito; non toccare file utente.
